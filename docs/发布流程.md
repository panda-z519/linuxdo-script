# 发布流程：GitHub 主源 + Greasy Fork 镜像

本仓库的两个脚本只有一个真源：GitHub。Greasy Fork 是镜像和分发入口，不单独维护代码。

- **GitHub**：代码、版本号、历史版本、文档与测试的唯一真源。
- **Greasy Fork**：从 GitHub 源码同步的镜像，负责搜索曝光和 Tampermonkey 一键安装。
- **`versions/`**：已发布版本的只读快照，用于回滚与对照。

## 版本号规则

- 唯一来源是脚本头部的 `// @version`，两个脚本各自独立演进：`save-obsidian` 走 `0.9.x`，`topic-reader` 走 `5.0.x`。
- `package.json` 的 `version` 只跟工具链对齐 `save-obsidian`，不参与发布判断。
- 改了脚本就必须提版本号，否则 GitHub 和 Greasy Fork 都不会把更新推给用户。

## 每次发版的步骤

```sh
# 1. 改脚本
#    userscripts/<脚本>/<脚本名>.user.js

# 2. 提版本号（脚本头 @version）

# 3. 归档当前版本
npm run archive-version

# 4. 本地门禁
npm run check
npm test

# 5. 提交并推送（脚本 + versions/ + 文档放同一提交）
git add -A
git commit -m "<改动说明>（<新版本号>）"
git push origin main

# 6. 确认发布地址已经生效（必要时等 GitHub 刷新，最多重试约 18 秒）
npm run check-published

# 7. 在 Greasy Fork 对应脚本页触发一次源码同步，确认页面版本号等于 @version
```

`npm run check-published` 会拉取两个脚本的 raw 地址，和本地 `@version` 比对，避免「push 成功但用户仍拿到旧版本」。

## Greasy Fork 侧的镜像配置

首次发布时在 Greasy Fork 创建脚本，填入下表信息；之后每次只需触发同步。

| 字段     | 保存到 Obsidian                                                              | 弹框阅读                                                             |
| -------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 脚本名称 | linux.do 帖子保存到 Obsidian                                                 | linux.do 帖子弹框阅读                                                |
| 源码地址 | `userscripts/save-obsidian/linux.do 帖子保存到 Obsidian.user.js` 的 raw 地址 | `userscripts/topic-reader/linux.do 帖子弹框阅读.user.js` 的 raw 地址 |
| 许可证   | MIT（脚本头已声明）                                                          | MIT（脚本头已声明）                                                  |
| 语言     | 中文（简体）                                                                 | 中文（简体）                                                         |
| 描述     | 取自[保存脚本使用说明](<Obsidian 保存脚本使用说明.md>)                       | 取自[阅读脚本使用说明](帖子弹框阅读脚本使用说明.md)                  |

raw 地址形如：

```text
https://raw.githubusercontent.com/panda-z519/linuxdo-script/main/userscripts/<脚本目录>/<脚本文件名>
```

脚本头里的 `@updateURL` / `@downloadURL` 已经写成同一个地址，可用 `npm test` 校验它没有写错。

## Greasy Fork 的注意事项

- Greasy Fork 要求脚本开源可读，`0.9.x` / `5.0.x` 都是明文脚本，不要提交压缩或混淆版本。
- 从 Greasy Fork 安装的用户会走 Greasy Fork 的更新通道，脚本头里的 `@updateURL` 会被站点接管；因此 GitHub 与 Greasy Fork 是两条更新通道，但版本号必须一致。`npm run check-published` 只校验 GitHub 侧，Greasy Fork 侧靠同步后人工核对版本号。
- 不要在 Greasy Fork 的网页编辑器里直接改代码，那会和仓库分叉；所有改动都回到仓库，再同步过去。
- 仓库里脚本路径一旦变化，Greasy Fork 的源码地址要同步修改，否则同步会 404。2026-11 整理目录时脚本从仓库根目录移到 `userscripts/<脚本>/`，老的 raw 链接即已失效。

## 回滚

- 代码回滚：从 `versions/<脚本>/<版本>/` 取对应文件复制回 `userscripts/`，提一版新版本号后重新走发布流程；或 `git revert` 对应提交再 push。
- 用户侧回滚：让对方从 `versions/` 里的文件手动替换，或安装 Greasy Fork 上保留的历史版本。

## 排错

- `check-published` 报版本不一致：确认已 push 到 `main`（不是其它分支）、文件名大小写一致、脚本仍在 `userscripts/<脚本>/` 下；GitHub 偶尔有缓存，重试一次。
- Greasy Fork 同步失败：源码地址 404（路径改过）、脚本头缺少 `@name` 或 `@version`、或脚本里出现 Greasy Fork 不接受的内容（远程混淆代码、压缩脚本）。

## 与自动测试的关系

`npm test` 里与发布相关的门禁：

- `tests/versions.test.js`：`@version` 与 `versions/` 目录一致、归档版本不高于当前版本、归档内容与当前脚本一致、`@updateURL` / `@downloadURL` 指向仓库中的真实路径。
- `tests/actions-position.test.js`、`tests/ui-layers.test.js`、`tests/topic-reader.test.js`：脚本行为回归。

发布前这些必须全绿，它们是「提交即发布」的最后一道保障。
