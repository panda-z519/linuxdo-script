# Agent Note: 原生帖子页弹框

Status: implemented

## Problem

用户要求弹框除侧边栏外具备直接打开 linux.do 帖子时的全部内容和操作。自行请求主题 JSON 并重绘帖子只能覆盖已知字段，无法持续复现 Discourse 的点赞、回复、回应、用户卡、图片预览、楼层导航、通知和插件功能。

## Decision

`linux.do 帖子弹框阅读.user.js` 在捕获阶段识别同源主题链接的普通左键点击，记录来源 URL、滚动位置和触发链接，但继续让当前已运行的 Discourse 单页路由处理点击。脚本不创建 iframe，也不重复加载页面。

路由切换期间，脚本保存原生 `#main-outlet-wrapper` 的 DOM 位置，将该节点临时移动到居中磨砂弹框的内容槽，并隐藏侧边栏。帖子正文、分页和所有站内操作仍由 linux.do 当前应用负责。展开或关闭时将主内容节点恢复到原位置；关闭还会返回来源 URL，并恢复列表滚动位置与触发链接焦点。

用户脚本保持 `@inject-into content`，保证 Safari Userscripts 使用内容隔离环境。纯函数在无 DOM 环境下导出，用于回归主题 URL、点击条件和来源页状态。

使用说明位于 [帖子弹框阅读脚本使用说明](../../../../docs/帖子弹框阅读脚本使用说明.md)。

## Alternatives considered

### 自行请求 JSON 并重绘完整帖子

自绘能控制视觉样式，也能对正文做严格白名单清理。但它必须复制 Discourse 持续变化的数据契约、插件内容和写操作，之前实现已无法满足“原始页面全部功能”，因此被当前决策完全取代。

### 直接导航原始帖子

直接导航天然拥有全部能力且最稳定，但会离开列表并丢失用户要求的弹框阅读体验，因此保留为工具栏中的“在当前标签打开”。

### 通过新窗口打开帖子

新窗口同样保留原生行为，但窗口管理和弹窗拦截体验不稳定，也不符合当前页覆盖阅读的目标。

## Consequences

弹框会自动获得 linux.do 当前页面提供的点赞、回复、用户卡、图片预览、楼层导航和后续站点升级，维护范围缩小为链接识别、阅读模式样式和关闭返回。用户的站内操作由原站完成，不产生第二套权限或写接口，也不重复启动 Discourse。

该方案依赖 linux.do 保持单页客户端路由，以及 `#main-outlet-wrapper` 和侧边栏选择器。如果这些 DOM 或路由契约变化，帖子仍会原生打开，但弹框样式或关闭返回可能退化。关闭使用浏览器历史返回来源页；在弹框内产生额外路由记录时，可能需要再次返回。

弹框与保存脚本悬浮界面的层级约定（谁压在谁上面）单独记录在[保存按钮被阅读弹框遮挡](../bug-fix/2026-11-01-保存按钮被阅读弹框遮挡.md)。

## Verification

`npm test` 验证主题 URL、跨站拒绝、普通点击条件、来源页状态和 Safari Userscripts 元数据；`npm run check` 验证两个用户脚本语法。真实 Safari 仍需用已更新的 Userscripts 副本验证原生路由、当前 DOM 选择器和关闭返回。
