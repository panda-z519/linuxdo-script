# Agent Note: 保存按钮被摆到视口外

Status: implemented

## Problem

保存脚本的按钮组是固定定位、可拖拽、位置存进 `GM.setValue`。用户报告「按钮总是出不来」，而在真实 Safari 上实测发现按钮其实在 DOM 里，只是被摆到了视口右下角之外：

```json
{"viewport":[2672,1548],"actions_style":{"left":"2660px","top":"1536px","right":"-121px","bottom":"-48px","display":"flex"}}
```

`left = innerWidth - 12`、`top = innerHeight - 12` 这组数字暴露了原因：`create_actions()` 先调 `restore_actions_position()`，它 `await GM.getValue(...)`；等待期间 `sync_actions_visibility()` 已经把按钮组设为 `hidden`（当前是列表页）。恢复位置时用 `actions.getBoundingClientRect()` 做边界夹紧，而隐藏元素的 rect 是 `0×0`，于是

```text
max_left = innerWidth - 0 - 12   // 2660
max_top  = innerHeight - 0 - 12  // 1536
```

按钮组的左上角被放到视口右下角，等进入主题页显示出来时，整组有 121px 宽、48px 高落在视口外，只剩一条边可见。因为位置每次加载都会这样重算，用户看到的现象就是「永远看不到按钮」。

`0.9.6` 之前只验证过 Chromium 里的 mock 页面，那里 `GM.getValue` 返回 `null`（没有历史拖动位置），根本走不到这条路径，所以没暴露出来。

## Decision

按钮尺寸改为按真实布局测量，位置在三个时机重新夹紧：

- `measure_actions()`：rect 宽高为 0 时，临时 `hidden = false` + `visibility: hidden` 量出真实尺寸再恢复，夹紧计算 never 使用 0×0。
- `sync_actions_visibility()`：按钮从隐藏切到显示时调用 `keep_actions_position_in_view()`，纠正历史遗留的越界位置，用户不需要手动拖回来。
- `resize` 监听：窗口或缩放变化后重新夹紧，避免换显示器、改缩放后按钮跑到视口外。

`clamp_actions_position(left, top, rect, viewport)` 改为纯函数（viewport 作为参数），并通过 `module.exports` 暴露给 `tests/actions-position.test.js`；脚本在无 `document` 环境下提前返回，不再执行界面逻辑。

## Alternatives considered

### 只在保存位置时记录，不在显示时纠正

改动最小，但救不了已经被写坏的现状：老版本算错的位置在新的夹紧逻辑生效前就已经落到元素上，而且窗口缩放后仍会越界。用户得先手动把按钮拖回来，正是他们已经放弃的操作。

### 干脆不保存拖动位置

彻底绕开这一类问题，但用户明确要求「按住按钮组拖动位置」并且位置要记住，牺牲功能换稳定不成立。

### 用 `offsetWidth`/`offsetHeight` 代替临时显示测量

`offsetWidth` 在 `display: none` 下同样是 0，隐藏状态下拿不到尺寸；其它间接测量（克隆节点、`getComputedStyle` 求和）要么受字体和外部样式影响，要么代码更绕。临时显示 + `visibility: hidden` 复用了浏览器真实布局，一次同步读回，成本可以忽略。

## Consequences

收益：按钮在有拖动历史、缩放变化和小窗口下都稳定落在视口内；`hidden` 期间不再产生错误位置；越界的老位置会自动被纠正。

代价：`measure_actions()` 会在隐藏状态下短暂修改 `hidden` 与 `visibility`，如果测量期间发生重排会影响性能（每次夹紧一次同步布局，可忽略）；`clamp_actions_position` 多了一个 `viewport` 参数，调用点需要传 `window.innerWidth/innerHeight`。

这个缺陷与[保存按钮被阅读弹框遮挡](2026-11-01-保存按钮被阅读弹框遮挡.md)是两个独立问题：前者是位置算错，后者是层级被遮。用户当前装的是 `0.9.6`，只有层级修复；位置修复在 `0.9.7`。

## Verification

- 真实 Safari（Safari 27，`safaridriver` 的远程自动化未开启，改用 AppleScript `do JavaScript` 驱动已登录页面；CSP 阻止 `eval`，新代码通过页面自带 nonce 注入 `<script>` 执行）：
  - 修复前：按钮 `left:2660 top:1536`、`right:-121px`，`elementFromPoint` 在按钮中心返回 `null`。
  - 修复后（0.9.7 注入）：`right:0`、`bottom:12px`，`rect=[2526,1476,108,60]` 完全在 `2672×1548` 视口内，`elementFromPoint` 命中 `BUTTON#ldo-obsidian-save`，`elementsFromPoint` 栈顶就是按钮。
  - 触发 `resize` 后自动重新夹紧到 `2512.9/1476`，仍然完全可见、可点击。
- `tests/actions-position.test.js` 覆盖纯函数：越界位置夹回 `{left:2510,top:1476}`、正常位置原样保留、极小视口仍留 12px 边距；并用源码断言锁住「隐藏时真实测量」「显示与 resize 时重新夹紧」两处实现。
- `npm run check`、`npm test`（19 项）通过。
- 未在 Safari 验证的部分：弹框阅读脚本没有安装在该浏览器里（页面无 `ldo-topic-reader-style`），层级修复仍以 Chromium mock 结果为准，等安装阅读脚本后再补一次真机确认。
