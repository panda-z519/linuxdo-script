# Agent Note: 保存按钮被阅读弹框遮挡

Status: implemented

## Problem

弹框阅读脚本用 `2147482998` 的遮罩和 `2147482999` 的弹框外壳覆盖整个视口，而保存脚本的悬浮界面一直是 `9999`、`10000`、`10001`。两个脚本同时安装后，只要弹框打开，右下角「保存到 Obsidian」按钮就被整块盖住。

实测（Chromium 打开模拟 linux.do 主题页，弹框打开后取按钮中心点）：修复前 `document.elementFromPoint` 命中 `#main-outlet`，即弹框内容，用户看到的现象是「按钮没加载出来」；点击该位置会命中遮罩，反而把弹框关掉。阅读脚本使用说明的验收标准要求「与已安装的 Obsidian 保存脚本共存时，保存按钮、设置弹框和保存预览不受影响」，两条要求此前互相冲突。

## Decision

层级数值是这两个脚本之间唯一的跨脚本契约，统一按下表分配，保存脚本负责让出下方空间：

| 层                                         | z-index    |
| ------------------------------------------ | ---------- |
| 阅读弹框遮罩 `#ldo-topic-reader-backdrop`   | 2147482998 |
| 阅读弹框外壳 `#ldo-topic-reader-chrome`     | 2147482999 |
| 保存按钮组 `#ldo-obsidian-actions`          | 2147483000 |
| 保存设置与预览 `#ldo-obsidian-modal`        | 2147483004 |
| 阅读模式下的原生编辑器、用户卡、站内对话框 | 2147483005 |
| 保存提示 `#ldo-obsidian-toast`              | 2147483006 |

约定两条硬性规则：

- 保存脚本的悬浮界面 must 始终高于阅读弹框外壳，否则弹框一开按钮就不可见、不可点击。
- 保存提示 must 高于 `2147483005`，这样回复框或用户卡在弹框内打开时，保存结果仍然可见。

两个脚本仍然独立安装、互不读取状态：契约只存在于 CSS 数值上，任一方未安装时另一方都按原样工作。

## Alternatives considered

### 让阅读弹框压住一切，保存按钮只在弹框外可用

最省事，也符合「模态层覆盖页面」的常见直觉。但保存脚本的使用场景恰恰是「正在读帖子时保存」，用户在弹框里读完全文正是要保存的时刻；把按钮藏起来等于让用户在两个脚本之间二选一。这条被验收标准直接排除。

### 把阅读弹框降到 `9000`/`9001`，让保存按钮自然浮在上面

只需改新脚本，已发布的保存脚本一行不用动，冲突面最小。问题是 linux.do 是 Discourse 单页应用，主题和插件会自带高层级浮层（用户卡、灯箱、通知面板），弹框必须压住站点自身界面；把弹框上限锁死在四位数量级，站点或插件某次升级提高层级就会击穿弹框。而保存按钮是「随时可点的操作入口」，本来就该高于模态层，选它做上层更站得住。

### 阅读模式下把保存按钮搬进弹框头部

视觉效果最干净，按钮不会浮在正文上。代价是两个脚本要互相感知：阅读脚本得知道保存脚本存在，保存脚本得在弹框开关时迁移自己的 DOM，且任一方单独升级就会破。这与「两个脚本独立启停、不共享状态」的设计边界冲突，收益不足以换取这种耦合。

## Consequences

收益：弹框阅读时保存按钮仍在，保存脚本的设置弹窗、预览和提示也都能覆盖在弹框之上；保存时的抓取逻辑不受影响，因为主题 URL 和正文 DOM 都在同一份文档里，弹框只是把 `#main-outlet-wrapper` 换了位置。

代价：按钮组会浮在弹框右下角，可能与楼层操作栏重叠，用户需要按既有拖拽能力挪开；两个脚本通过魔法数字耦合，任一方调整层级都要同步更新另一方的文档。为此把数值写进回归测试，避免只改一边。

用户侧影响有限：只有保存脚本需要升级，阅读脚本不变；单独安装任一脚本都不需要改动。

同一时期还发现另一个独立的「按钮看不见」原因——按钮位置被算到视口外，见[保存按钮被摆到视口外](2026-11-01-保存按钮被摆到视口外.md)。两个修复都在 `0.9.7` 里。

## Verification

- `tests/ui-layers.test.js` 解析两个脚本的 CSS 规则，断言「遮罩 < 外壳 < 保存按钮组」以及「保存提示 > 弹窗 > 弹框外壳」「保存提示 > 阅读模式原生浮层」，并断言保存脚本不再回退到 `9999`/`10000`/`10001`。临时把按钮组改回 `9999` 时该测试确实失败。
- 浏览器实测（Playwright + Chromium，临时 mock 页面通过 `--host-resolver-rules` 映射到 `linux.do`，未提交进仓库）：弹框打开后按钮中心点命中 `#ldo-obsidian-save`；点保存触发设置弹窗，弹窗以 `2147483004` 置顶且内容可交互；页面无脚本报错。
- 仍需在真实 linux.do + Safari 上确认一次：弹框内点保存按钮，按钮可点、弹框不被误关。
