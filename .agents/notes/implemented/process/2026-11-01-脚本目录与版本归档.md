# Agent Note: 脚本目录与版本归档

Status: implemented

## Problem

仓库根目录平铺着两个用户脚本，各自独立演进版本（`0.9.6`、`5.0.6`），文档、测试、原型挤在 `docs/` 一层，没有版本归档。后果是：

- 回滚只能翻 git 历史，而阅读脚本是在引入 git 记录之外开发的，历史里没有任何旧版本可供回滚。
- 脚本、文档、测试都在同一层，新增第三个脚本时无法判断哪个文件属于哪个脚本。
- `package.json` 的 `check`、`format` 路径写死两个文件名，加脚本就要改四处命令。
- 脚本管理器按 URL 自动更新，路径一旦随意变动，已安装用户会失去更新目标。

## Decision

按「稳定入口 + 版本快照」两层组织：

```text
userscripts/<脚本>/<脚本名>.user.js      当前版本，同时是安装地址
versions/<脚本>/<版本号>/<脚本名>.user.js  已发布版本的只读快照
```

- 脚本目录用小写英文 slug：`save-obsidian`、`topic-reader`；userscript 文件名保留中文 `@name` 措辞，因为两者用途不同——slug 给路径和命令用，文件名给用户识别用。
- 每个脚本目录只允许一个 `.user.js`，`versions/<脚本>/<版本>/` 也只允许一个。
- 归档由 `npm run archive-version`（`tools/archive-version.js`）生成：读当前脚本的 `@version`，复制到对应目录。已存在的同版本归档默认拒绝覆盖，内容有差异时报错并提示先提版本号，确认要覆盖需 `--force`。
- `tests/versions.test.js` 作为发布门禁：目录名与 `@version` 必须一致、归档版本不得高于当前版本、归档内容必须与当前脚本逐字节一致。
- 版本只从当前版本开始归档（`0.9.6`、`5.0.6`），不从 git 历史回填旧版本。

## Alternatives considered

### 完全按版本分目录：`versions/0.9.6/` 直接作为唯一入口

目录最干净，一个版本一个文件夹，天然不会写错版本。问题是用户脚本管理器的安装地址必须是稳定 URL，每次发版都换路径就意味着每次发版都要用户重新安装；而且两个脚本版本号不同步，按版本分目录会让「当前装的是哪个脚本的哪个版本」反而更难看清。

### 不建物理归档，只用 git tag + CHANGELOG

最省事，也符合一般软件仓库的做法，仓库不会出现「同一份内容存两份」。但脚本管理器无法从 git tag 安装：真要回滚时得先 checkout 旧提交、复制文件、再切回来，对「粘贴到 Userscripts」的实际使用方式几乎没有帮助。阅读脚本的绝大多数历史本来就不在 git 里，tag 也补不回来。

### 保留根目录平铺，只把文档按脚本分目录

改动最小，且完全不动安装地址。但根目录会随脚本数量线性变乱，且「哪个文件属于哪个脚本」仍要靠文件名猜；既然已经要动一次路径，就不如一次分到位。

## Consequences

收益：新增脚本只需要加一个目录，`check`、`format`、`archive-version` 都已按通配符配置；回滚变成「打开 `versions/` 下对应文件复制粘贴」；当前版本与归档版本的一致性由测试保证，不会出现「改了脚本忘了归档」。

代价与风险：

- 安装地址一次性变更，已安装用户需要重新粘贴一次脚本内容（或从新 raw 链接重装）。这是本次整理唯一对用户可见的破坏性影响，已写进 README 的版本说明与两份使用说明。
- 「当前版本」与「归档快照」内容重复存在于两个路径，靠 `tests/versions.test.js` 防止漂移。约定是：修改脚本 → 提 `@version` → `npm run archive-version`，三步同一提交。
- 新增 `tools/` 目录存放仓库维护脚本，与 `userscripts/` 分开，避免把开发工具当作用户脚本发布。

## Verification

- `npm run check` 通过（`node --check` 指向新路径的两个脚本）。
- `npm test` 15 项全绿，其中新增的 4 项覆盖版本归档：元数据可解析、目录名与 `@version` 一致、归档版本不高于当前、归档内容与当前脚本一致。
- `npm run archive-version` 重复执行输出「已归档，内容一致」，不会误写快照。
- 全仓 Markdown 相对链接扫描无死链（含 README、`docs/`、`userscripts/README.md`、`versions/README.md` 指向脚本和文档的链接）。
